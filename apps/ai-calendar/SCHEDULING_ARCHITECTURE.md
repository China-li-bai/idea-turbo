# 智能排班系统架构设计

## 1. 核心问题分析

### 1.1 边界条件挑战
- **员工数量可扩展性**：从几人到几十人、上百人
- **复杂度**：多班次、多约束、多目标优化
- **硬性约束**：必须满足的条件（法定工时、不可用日期等）
- **软性约束**：优化目标（员工偏好、负荷均衡等）

### 1.2 隐私保护挑战
- 员工信息（姓名、联系方式、偏好等）不能泄露
- 排班数据本地化存储
- AI辅助时不传输敏感数据

## 3. 算法设计

### 3.1 约束满足问题 (CSP) 建模

**变量 (Variables)**:
- 每个班次槽位：`ShiftSlot(date, shiftType)`
- 每个变量的可能值：可用员工列表

**约束 (Constraints)**:

#### 硬性约束 (Hard Constraints)
1. 员工不可用日期
2. 员工禁止的班次类型
3. 连续班次限制（如不能连续3个夜班）
4. 每日最大工作时长
5. 每周最大工作时长
6. 班次间最小休息时间

#### 软性约束 (Soft Constraints)
1. 员工偏好班次
2. 员工偏好休息日
3. 工作负荷均衡
4. 避免连续周末排班
5. 班次多样性

### 3.2 求解策略

#### 第一阶段：贪心初始化
1. 按优先级排序约束
2. 逐个分配班次
3. 优先满足硬性约束
4. 记录冲突点

#### 第二阶段：局部搜索优化
1. 识别冲突和不满意的约束
2. 尝试交换员工班次
3. 评估改进程度
4. 迭代直到收敛或达到最大次数

#### 第三阶段：AI辅助优化
- 使用本地AI（如Ollama）或轻量级模型
- 只发送抽象的约束描述，不发送真实员工信息
- 获取优化建议后在本地执行

## 4. 隐私保护机制

### 4.1 数据本地化
- 所有员工信息、排班数据存储在本地 IndexedDB
- 不向云端发送任何个人身份信息 (PII)

### 4.2 AI调用的隐私保护

#### 方案A：数据脱敏
```typescript
// 发送给AI的是脱敏数据
const sanitizedData = {
  employees: employees.map((e, idx) => ({
    id: `employee_${idx}`,  // 匿名ID
    unavailableDates: e.constraints?.unavailableDates?.length || 0,  // 只发送数量
    preferredShifts: e.preferences?.preferredShifts?.length || 0,
  })),
  constraints: abstractConstraints,  // 抽象约束描述
  shiftCount: shifts.length,
};
```

#### 方案B：纯约束描述
```typescript
// 只发送规则描述，不发送具体数据
const aiPrompt = `
请提供排班优化建议，满足以下约束：
- 有 ${employees.length} 名员工
- 有 ${shiftTypes.length} 种班次类型
- 某些员工在特定日期不可用
- 需要保证工作负荷均衡
- 避免连续夜班

请以JSON格式返回优化策略。
`;
```

#### 方案C：本地优先 + AI可选
- 默认使用本地算法，完全不调用AI
- 用户可选择启用AI辅助
- AI辅助时提供明确的隐私提示

### 4.3 透明度
- 明确告知用户哪些数据会被处理
- 提供数据导出和删除功能
- AI调用前显示确认对话框

## 6. 关键技术选型

| 组件 | 技术方案 | 说明 |
|------|----------|------|
| 约束求解 | 贪心 + 局部搜索 | 本地执行，无隐私风险 |
| 本地存储 | IndexedDB | 完全本地化 |
| AI辅助 | 可选Ollama/OpenAI | 默认禁用，用户选择 |
| 数据脱敏 | 匿名化处理 | AI调用前处理 |
