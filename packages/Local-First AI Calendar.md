# 架构设计文档：Local-First AI Calendar (代号：No-Bullshit-Calendar)
**作者：** (模仿 Linus Torvalds)
**状态：** Draft

听着，我受够了现在市面上那些所谓的“AI 日历”。这些愚蠢的 SaaS 公司把你每天要见谁、去哪里、谈什么机密，全都一股脑打包塞进他们那堆满屎山代码的云端数据库里。这简直是**脑残（brain-damaged）**。

隐私不是你在用户协议里写两句公关废话就能解决的。**真正的隐私在物理层面上只有一个解法：让数据统统留在用户的本地硬盘里，不要发往网络。**

这是我们构建这个 Web 智能日历的底层逻辑。我们不需要后端的微服务集群，不需要 Docker 容器，不需要那些花里胡哨的云原生垃圾。我们只用现代浏览器的底层能力（WASM 和 WebGPU）来做真正的工程。

以下是架构说明。如果你连这都看不懂，那你可能更适合去写那些用 Electron 打包的 2GB 内存占用记事本。

---

### 1. 核心架构哲学：把服务端干掉

整个系统是一个 **纯前端应用 (Pure Web App)**。

你的浏览器就是计算节点。我不关心你是用 React 还是 Vue，只要你别弄出 10MB 的 bundle size 就行。我们的目标是：即使用户拔掉网线，向量索引和日程写入也必须要在 10 毫秒内完成。

### 2. 存储层：EdgeVec (跑在 WASM 上的利器)

现有的向量数据库（像 Pinecone 这种）就是来骗风投资金的。为了存几千条日历记录去调用 REST API？简直是在开玩笑。

我们用 **EdgeVec**。
*   **为什么：** 它是用 Rust 写的，编译成 WebAssembly (WASM) 直接在浏览器进程的内存里跑。没有网络 I/O 延迟，没有序列化开销。
*   **结构：** 所有的向量和元数据（标量）都在本地计算。我们不仅要算向量相似度，还要做严格的时间戳过滤（Timestamp Filtering）。如果你在找下周二的会议，别给我搜出去年大明湖畔的烂事。
*   **持久化：** 数据直接通过 `localforage` 落盘到浏览器的 `IndexedDB`。你自己的数据，存在你自己的 SSD 上，就这么简单。

### 3. AI 引擎层：本地化 Embedding (Transformer.js + WebGPU)

这是重头戏。绝大多数蠢材会把用户的日程明文发给 OpenAI 的 API 来生成 Embedding。恭喜你，你的底裤都交出去了。

在这里，我们必须把 Embedding 模型跑在本地：
*   **引擎：** 使用 **Transformers.js (v3)**。它能直接越过这该死的 JS 虚拟机，通过 WebGPU 调用你底层的显卡硬件。
*   **模型：** 选用 **`Xenova/multilingual-e5-small`**。
    *   别给我搞什么几十亿参数的巨无霸模型。日历应用只需要处理短文本。这个 384 维的小模型（量化后几十MB）完全够用了。首次加载丢进 Cache API，之后秒开。
    *   占用内存极小，哪怕你开着十个网页，日历也不会让你的浏览器 OOM（内存溢出）崩溃。
*   **使用警告：** 记住了，E5 模型是强依赖前缀的！存数据时加上 `passage:`，提问时加上 `query:`。这是底层矩阵乘法的数学要求，如果你忘了加导致搜索结果像一坨屎，别来提交 issue，那全是你自己的错。

### 4. 推理层：最小权限的 RAG（远程大模型 API）

我虽然讨厌云端，但我不是个瞎子。现在的浏览器里根本跑不动能在逻辑上帮你规划一整周复杂行程的大模型（LLM）。如果你硬要跑本地大模型，你的笔记本风扇会转得像直升机一样，然后电池在 20 分钟内耗尽。

所以，这一步我们向现实妥协，调用远程 API（比如 DeepSeek 或 Claude）。但我们有**严格的协议**：

1.  **绝对禁止（Zero-Tolerance）：** 永远不要把你整个日历的数据发给 API。
2.  **局部提取（RAG）：**
    *   用户提问 -> 本地 WebGPU 计算提问向量 -> 本地 EdgeVec 检索出 3 条相关日程明文。
    *   将这 3 条明文作为 Context（上下文）组装进 Prompt，发给远程 API。
    *   API 的功能仅仅是**阅读理解和自然语言组织**，它绝对触碰不到你日历的全局数据。

### 5. 数据同步 (Sync) 架构：自带存储 (BYOS)

既然是纯本地，跨设备同步（比如从公司电脑同步到手机）就是个硬骨头。

市面上常见的做法是建个中心服务器。**我们不这么干，我没空给你付服务器账单。**

采用 **BYOS (Bring Your Own Storage)** 模式：
*   我们提供标准的 WebDAV 接口，或者直接支持挂载用户的私有网盘（Nextcloud、iCloud Drive、Google Drive）。
*   同步的逻辑极其简单：将本地的 IndexedDB 序列化 -> 加上 AES-256 端到端加密 -> 变成一个 `.bin` 文件扔到用户的私人网盘里。
*   这样就算网盘公司被黑了，黑客拿到了一堆乱码，也根本不知道你明天下午两点要去见心理医生。
